# Siftwell: notes for AI coding agents

Siftwell is a self-hosted household job board: it fetches listings from employer career sites, filters them per profile, rates fit with Claude (via the Claude Code CLI), and tailors resumes. Plain Python (stdlib HTTP server) + server-rendered HTML/JS; no build step, no frameworks.

## Map
- `server.py`: HTTP server (`python server.py [port]`), all routes in `H.do_GET` / `H.do_POST`. POSTs need header `X-Jobboard: 1` and same origin. Access: from 127.0.0.1 directly, or a cookie set by `/?k=<access key>`. Current profile = `jb_person` cookie.
- `paths.py`: APP (repo), DATA (user data dir outside the repo; env `JOBBOARD_DATA` overrides; also holds the launcher's `port` and `server.pid`), RUNTIME (launcher's uv/Python/venv, per machine; env `SIFTWELL_RUNTIME` overrides), ASSETS, PACKS, `load_config()`, one-time `migrate()`.
- `people.py`: profiles, per-profile settings and prefs (`PREF_SCHEMA`).
- `jobfinder.py`: fetching (ATS fetchers), per-person filtering (`select_for_person`), scoring, board build. `extra_fetchers.py`, `smb_fetchers.py`, `ats_more.py` (Radancy, Eightfold, Avature; own robots.txt check + paced http; `scripts/test_ats_more.py`, fixtures in `scripts/fixtures_ats_more/`): more ATS fetchers. `ats_public.py` (AppliTrack/Frontline, SchoolSpring, Jobvite, built on ats_more's polite http; `scripts/test_ats_public.py`, fixtures in `scripts/fixtures_ats_public/`). NEOGOV/GovernmentJobs and PeopleAdmin are deliberately not read: their robots.txt forbids all crawlers. `company_add.py`: add a company from a careers link (detect + verify).
- `ai_score.py`: Claude Match ratings (Haiku → Sonnet → Opus funnel; every run is capped by `ai_score.RUN_LIMITS`, see `scripts/test_quickfix.py`). `claude_usage.py`: one line per Claude call in `DATA/claude_usage.jsonl` (tokens and counts only, never prompt text), shown in Settings → Claude usage. `pivot.py`: Target-tab ratings. `claude_cli.py`: wrapper around `claude -p`. `nlsearch.py`: natural-language search.
- `lookfor.py`: the per-profile "what to look for" sheet (`DATA/people/<id>/lookfor.json`: most recent title, titles in weight tiers, O*NET occupations, skills, field; the person's chips and removals always win) and the free **Relevance** score (`Scorer`, plain code, every job; `job["rel"]`, `job["rel_why"]`). Built from the person's own data widened with the O*NET extract `assets/onet/onet.json.gz` (rebuild: `scripts/build_onet.py <unzipped O*NET text download>`; attribution in `assets/onet/NOTICE.txt` and docs/GUIDE.md); Claude's ideas arrive in `resume.build_profile`'s own call (`look_for`) or one small Haiku call (`suggest`, only when the titles changed; never at upgrade). Learning from marks: `lookfor_learn.json` (bounded nudges, reset on the profile page). Used by: the title filter (`jobfinder.person_cfg` → `CFG["title_words"]`, whole words; `title_rule: "builtin"` profiles only get titles they add themselves), rating order (`ai_score.pick_order`), Best bets for unrated jobs (`jobfinder.unrated_match`), Workday full text up front (`jobfinder.fetch_wanted`; other postings are "lazy" rows, text fetched by `jobfinder.lazy_text` on open / before rating). **Nothing in it may enter a rating fingerprint or cache key.** Tests: `scripts/test_relevance.py <scratch>`.
- Employers: there are no shared company lists any more. A company's `sets` holds only `own-<pid>`, `near-<pid>` and `all`; people see one thing, "Your employers" (`people.company_sets`). `catalog.move_lists()` (run by `catalog.migrate()`) moved the old `tech` / `ops` / `nonprofit` lists onto each profile's own list, once; never add a default list back.
- `report.py`: the board page. `HEAD`/`BODY`/`TOOLS` are plain strings; `SCRIPT` is a **raw** string holding all board JS. Output: `DATA/people/<id>/report.html`.
- `appupdate.py`: Siftwell's own update check/installer (GitHub Releases, once a day; Settings → About & updates; banner on the board and Settings; routes `/api/app-update*` wired in server.py).
- `backup.py`: Backup & move (Settings pane + welcome link): export/restore the whole DATA folder as a zip; routes under `/api/backup/` are wired in server.py via `backup.configure`.
- `first_search.py` (offline tests: `scripts/test_first_search.py`): "Start my job search" (last /setup screen + the empty board's Start card): first the Siftwell directory's employers near the person go on `near-<pid>` (`directory.apply`, no Claude), then Claude's Find employers only if they ticked "Find more with Claude" (employer_finder via catalog_api's Find thread, medium size; never by default), then the first check, staged (`_check`: the watched companies never fetched yet, in chunks through `server.run_update --only`, most nearby jobs first, boards rebuilt as it goes; "what is left" is just companies with no fetch yet, so Pause, a crash or a restart lose nothing and the board offers Continue checking); `GET /api/search` (plan + progress), `POST /api/search/start {find, directory}`, `POST /api/search/continue`, `POST /api/search/pause`, `/api/status` carries `check`; offline tests for this and the directory work: `scripts/test_coverage.py`; and `/api/setup/finish {search, find}`. Settings key `search_started`.
- `directory.py`: the Siftwell employer directory, app side: downloads whole-state shards (`states/<ST>.json.gz`, `states/remote.json.gz`, job snapshots `jobs/<ST>.json.gz`) + `manifest.json` (SHA-256 checked) from the repo's `index` branch on raw.githubusercontent.com into `DATA/directory/`, at most weekly, offline from cache; `apply(pid)` adds employers within the radius to `near-<pid>` once each (`DATA/directory/people/<pid>.json` remembers, so removals stick); offline / state not published: the shipped national packs (`packs/us-large-employers*.json`, read-only; not dc-area) go on as "starters" and `prune_starters(pid)` (after the fetch) drops those with no jobs near / remote; `directory_jobs` fetcher (registered in `jobfinder.load_extra`, netsafe rule registered at import) turns snapshot postings (USAJOBS, CareerOneStop, HN) into normal listings; weekly background refresh; Settings pane "Employer directory"; routes `GET /api/directory`, `POST /api/directory/apply {fetch}`. Test hooks: `SIFTWELL_DIRECTORY_URL=<base>` (http://127.0.0.1:port/... or file:///...), `SIFTWELL_DIRECTORY_DELAY=<s>`.
- `localdir.py` + `index_build/local.py` (offline tests: `scripts/test_localdir.py`): **Build my own directory**, the employer directory read on the person's own computer (no Claude, no GitHub needed). "Where my directory comes from" = `directory.prefs()["source"]`: `shared` (default) / `local` (the app never contacts the index branch: `directory._get` refuses) / `both` (merged per employer in `directory._merge`, newer reading wins); kept in `DATA/directory/prefs.json` for the whole household. The build is a child process (`frozen.command("dirbuild", ...)` = `localdir.py --root ...` from source, `Siftwell.exe --dirbuild ...` installed; below-normal priority; stops when the server is gone) that starts from the seed list (`assets/directory/seed.json.gz`, `index_build/seed.py`; made by `scripts/make_seed.py` from a builder state, refreshed by releases with `scripts/refresh_seed.py`, and by the app from the published directory when that is in use) and reads boards with the weekly builder's own code (`build.read_tenant`, same robots.txt / pacing / lanes / per-board limits), boards last seen hiring in the person's states first. Everything it writes is under `DATA/directory/local/` (`tenants.json.gz` + `journal.jsonl` = resumable state, `build.json`, `states/<ST>.json.gz` in the published format, `manifest.json`, `index.json.gz`, `progress.json`, `control.json`). **Polite by design** (thousands of home users may run it): every request of a builder process (the weekly build and the local build, including the app's own readers) goes through `index_build/net.install()`, which paces per PROVIDER (`net.PROVIDERS`: about 1 request/s and 1-2 connections for shared multi-tenant systems such as Paylocity, UKG, ADP, Workable, Taleo; every Workday tenant host is one provider; an employer's own domain is its own), asks for gzip everywhere, and makes a provider rest on 429 / 503 / dropped connections (Retry-After honoured); speed comes only from reading many different providers side by side. Directory reads are LIST ONLY: `extra_fetchers.wanted()` answers no when the config carries `_detail_budget` (set by `readers.generic`), so no per-posting page is fetched (two at most, when an employer's name must be learned). Never raise a provider's pace or add per-posting requests to a directory read without measuring. The breaker in `local.py` (`BREAK_AFTER` / `COOL_SECS`) is only the last resort. Data use shown in Settings comes from bytes counted on the wire (`build.json` `use`; `localdir.data_use`); on Windows a metered connection is detected (`localdir.metered`) and background builds don't run on it. `localdir.progress(pid)` is the build's line in `first_search.progress` (kind `dirbuild`, `"blocking": False`: it never holds Find new jobs up). Employers found near a person are added as it goes only when they asked (`control.json` `add`), as ONE undo batch (`directory.apply(tag=...)`). Weekly upkeep after a finished pass (`local.WEEKLY_MINUTES`, never while a fetch runs). Optional discovery from Common Crawl is off by default, slow, and cached 30 days (`directory.prefs()["discover"]`). Routes: `GET /api/localdir`, `POST /api/localdir/start {add, fresh}`, `/api/localdir/pause`, `/api/localdir/prefs {source, discover}`. Test hooks: `SIFTWELL_LOCALDIR_DELAY=<s>`, `SIFTWELL_LOCALDIR_LIMIT=<n>`. Never point a test build at real data, and keep real-network test builds short: they visit real employers' sites.
- `scripts/build_index.py` (command line only) + `index_build/` (a top-level package that SHIPS with the app, also inside installed builds: imported by name, never by "is the .py on disk"; `frozen._check_imports` asserts it and the seed load; both PyInstaller specs list it): the directory builder (stdlib; run weekly by `.github/workflows/index.yml`, which force-pushes one commit to the `index` branch and also publishes `seed.json.gz` there). `systems.py` = table of job systems (Common Crawl SURT prefixes, crt.sh domains, regex, careers URL: one row per system), `cc.py` (Common Crawl index via cluster.idx + range reads), `ct.py` (crt.sh), `gov.py` (IRS BMF, DOL LCA file, Web Data Commons domains; name -> board by slug, no LLM), `readers.py` (where each board hires; light readers + the app's FETCHERS), `postings.py` (USAJOBS / CareerOneStop with secrets, HN Who is hiring, The Muse), `net.py` (robots.txt, pacing, UA), `build.py` (orchestration, state in `_state/`, shards, manifest). `seed.py` (the compact seed list), `local.py` (the app's own build, see above). One code path: the weekly build and the app's build share `build.read_tenant`, `build.live_boards` and `build.write_states`. Local sample: `python scripts/build_index.py --out <scratch> --work <scratch> --states OH,CO --limit 2000 --minutes 60`.
- Other pages: `settings_page.py` (/settings), `setup_page.py` + `setup_flow.py` (/setup), `welcome_page.py` (no profiles yet). `connect_claude.py`: the inline Connect Claude card (install + sign in) used by setup; test hook `SIFTWELL_TEST_CLAUDE_EXE=<fake claude>`; Claude Code lookup paths in `osdeps.find_exe` (`scripts/test_find_exe.py`).
- `resume.py`, `tailor.py`, `review.py` (Astra, via Codex CLI), `interview.py`, `highlights.py`, `requirements.py`, `target.py`, `geo.py` (offline geocoding from `assets/geo`).

## One progress line, honest numbers
- Every page shows the SAME plain progress line, from `first_search.progress(pid)` (sent as `progress` by `/api/status` and `/api/search`): "Checking employers: 84 of 1,104 · your board fills in as we go", "Finding new jobs: 12 of 40 employers". Never show the fetch's raw output to users (only behind Details on the Employers page's Finding new jobs section, while it runs), and never add a second indicator. Counters of a staged check belong to the run (`first_search._RUN`) and never go down.
- Time estimates come from `first_search.estimates` / `fetch_minutes` (real company count and measured seconds), never a fixed number.
- "Build my own directory" has the same one line ("Building your directory: 1,240 of 6,300 job sites checked · 212 employers near you so far", `localdir.progress`); its time estimates come from seconds measured per job system (`localdir.estimate`: on this computer once there are enough reads, before that the weekly builder's from the seed), never a fixed number.
- Employers are never added blindly: `directory.preview` (count, openings, time), a choice of all / top N, and `directory.undo`. When the directory is unreachable, say so; the shipped starter list is used only by the first search (`apply(starters_ok=True)`).
- Names: "Find new jobs" (not Update / Fetch), "Employers" for the /catalog page, no model names (Haiku / Sonnet / Opus) in main labels, no internal names (tier ids, job-system ids) in what users read.

## Conventions
- Keep each file's existing line endings (some are CRLF, some LF). Never put a raw newline inside a JS string literal; use `\n`.
- After editing page JS, syntax-check it: write `re.sub(r"</?script>", "", report.SCRIPT)` (or the page's script) to a temp `.js` and run `node --check`.
- Boards re-render automatically at server start when `report.py` is newer than a board (`refresh_stale_boards`), so restart the server after editing `report.py`.
- Visual style: reuse the CSS custom properties at the top of `report.HEAD` (light + dark). Pages must work at 375px wide with no horizontal scroll.
- Never write into the app folder at run time (everything goes to DATA or RUNTIME), so users can delete it and download a new release; `scripts/release_check.py` checks this.
- Claude rating fingerprints/cache keys (`ai_score.fingerprints`, `pivot.cache_keys`) must depend only on the person's data, never on prompt/model/schema text. Bump `RATING_FORMAT` only to invalidate ratings on purpose (costs users tokens; announce it).
- No new dependencies without asking. Python 3.12, stdlib first.
- Never commit, push, or change git config unless the project manager asks. Don't commit user data (it lives outside the repo anyway).

## README must always match the app
`README.md` is the short front page (keep it ~60 lines: pitch, downloads, 3 steps, a few bullets, links), `docs/GUIDE.md` is the user manual (a Quick start on top, then every page and setting, in plain language with no jargon) and `docs/ADVANCED.md` holds the rest (portable / ZIP / uninstall / where files are kept / manual install / troubleshooting), all for people who barely know GitHub. **Any change that alters what users see or do (install steps, pages, buttons, settings, defaults, requirements, where data lives) must update docs/GUIDE.md in the same change**, in plain language, and README.md only if the essentials change. Don't describe features that aren't built yet except in the clearly marked "coming next" status line. Reviewers check this too.

## Testing
- Run a test server on its own port with its own data: `JOBBOARD_DATA=<scratch dir> python -X utf8 server.py <port>`. Never point tests at a real user's data folder.
- **Don't spend the user's Claude plan in tests.** Always run test servers and scripts with `SIFTWELL_FORBID_CLAUDE=1` (it blocks every Claude call and logs attempts to `DATA/forbidden_claude_calls.log`), even when you don't expect Claude to be called: rebuilds, restores and settings saves can start the automatic quick check. Use `SIFTWELL_CLAUDE_STUB` or stubbed functions for Claude-dependent features. Only lift the block for a tiny run (≤5 jobs) when your brief explicitly allows it.
- **No Claude needed to use Siftwell.** `claude_cli.claude_ready()` (installed + signed in, cached 30 s; `claude_cli.state()` says "ready" / "signed_out" / "not_installed") gates every Claude feature. When it is false: the board shows one banner and a "—" Match, the board is ordered by Relevance then Appeal (by Appeal when the profile has no job title), Tailor / Re-rate / Target suggestions explain instead of failing (`NEEDS_CLAUDE` routes in `server.py` answer 409 `needs_claude`), `/api/search` falls back to `nlsearch.keyword_search`, the funnel and Target ratings skip quietly (status `no_claude`), and `/profile` + `/setup` offer "Fill in my profile myself" (`manual_profile.py`, `resume.save_manual`, `/api/profile/manual`, `/api/resume/prefill`). New Claude-dependent features must check `claude_ready()` and show the same prompt (`Connect Claude to get ... → Settings → Get started`).
- **No industry or author assumptions.** Siftwell is for anyone in any line of work: no built-in job-title vocabulary, company lists, pay floor or level for new profiles (`people.DEFAULT_SETTINGS`; profiles from before keep theirs through `people.LEGACY_MISSING`). `python -X utf8 scripts/test_quickfix.py <scratch>` checks this, the US/foreign place rule (`geo.looks_foreign`), whole-word title excludes and the rating limits, offline.
- **Astra/Codex in tests:** set `SIFTWELL_PRETEND_NO_CODEX=1` so a test tailoring never starts a real Codex review (Codex may be installed on the machine).
- **Test the no-Claude experience** with env `SIFTWELL_PRETEND_NO_CLAUDE=1` (makes `claude_cli.path()` None, so `claude_ready()` is False everywhere, including child processes). Unset it to get the normal behaviour back.
- Verify UI in a browser at desktop width and 375px, and check the console for errors.
- Stop only processes you started. Restore any setting you change while testing.
- Two things that surprise in tests: (1) a scratch data folder that already has a profile (`people.json`) when the server first starts counts as an existing household, so phone/LAN access is switched ON and the server binds `0.0.0.0`; a brand-new install (no profile yet at first start) stays on `127.0.0.1`. For a pre-seeded scratch folder write `network.json` `{"lan": false}` before the first start. (2) the profile cookie `jb_person` belongs to the host, not the port: every test server on `127.0.0.1` shares it in the same browser, so another agent's tab can set "your" profile. Don't change the cookie in a shared browser; give your test data a single profile (an unknown id falls back to the first profile).
- **Stop must never stop "whatever is on the port".** `app_window.stop_server` / `stop_recorded` (tray, window close, `--stop`), `tools/launcher.ps1 -Stop` and `Stop Siftwell.command` only stop the pid in THIS data folder's `server.pid` / `window.pid` / `tray.pid`, after checking the process is this app folder's Siftwell (exe / command line) and was not created after the pid file was written (reused pid). No port-to-pid lookups, no command-line scans. Never add one. A stop test must use scratch `JOBBOARD_DATA` and your own test ports: `python scripts/test_stop.py <scratch> [port port]`.
- **App updater** (`appupdate.py`, Settings → About & updates, banner on board + Settings): test against a fake release server, never the real GitHub or a real installer. Env overrides (tests only): `SIFTWELL_UPDATE_API=<base url>` (default `https://api.github.com`; the request then uses plain urllib, because netsafe refuses local addresses), `SIFTWELL_UPDATE_DELAY=<s>` (first automatic check, default 15), `SIFTWELL_UPDATE_RUNNER="<python> <stub.py>"` (forward slashes; run with the downloaded file + the silent flags instead of running the file itself, and makes a source copy act as an installed one). `python scripts/test_updater.py <scratch> [app port] [fake port]` runs the whole suite (newer / same / older / 404 / 403 / 429 / timeout / auto on-off / stub installer download → verify → launch → exit / bad checksum / wrong size / ZIP copy). State: `DATA/app_update.json`; downloads: `DATA/_updates/`. The repo is the constant `appupdate.REPO`.
